mesnos en bref

mesnos est un serveur auto-hébergé (un Raspberry Pi) et un ensemble d’outils de musique qui tournent dessus. C’est un outil personnel, pour son propriétaire et Laetitia : apprendre des chansons pour des ateliers de musique trad (irlandais, fest-noz, bal folk), garder un recueil de chansons avec accords, réviser avec des lecteurs à boucles. Certains contenus se partagent par lien public ; les partager avec un groupe de musiciens est une piste ouverte.

Les principes qui comptent pour le design :

  • Chaque service tourne seul. Si l’un tombe, les autres perdent une fonction, pas tout.
  • Statique d’abord. Le site learnsong est généré ; songbook n’a aucune étape de build côté navigateur.
  • Une stack simple. Web components Lit et JavaScript sans framework lourd.
  • Une seule bibliothèque d’interface. Un motif qui manque va dans components, pas dans la feuille d’un site.

  • Se connecter. Une page protégée renvoie vers la page de connexion de users, puis revient à la page demandée. La session se renouvelle seule tant qu’une page est ouverte ; si elle expire, un bandeau le dit et le travail en cours est gardé.

  • songbook → learnsong (prévu) : songbook servira de source de chansons à learnsong, sans fusion.

Les applications

Six captures choisies par application ; toutes les autres sont dans la galerie. Cliquer une image l’agrandit.

learnsong · le site

réviser une chanson · tout compte connecté · 17 captures

Le cœur de l’usage. Les chansons sont rangées par personne → année → atelier → chanson. Une page de chanson réunit ce qu’il faut pour la travailler : les notes en Markdown, une grille d’accords (notation texte SNHT), des lecteurs à boucles (YouTube, vidéos et audios d’atelier ; boucle A-B, vitesse, transposition, forme d’onde ; les audios sont en mode minimal et se déplient), les PDF et liens, et le contenu importé des plateformes de cours.

À noter : pas de barre de navigation ni d’identité de site ; l’accueil est une liste à puces ; l’accès à l’admin est un ⚙️ discret en bas à droite, visible de tous.

learnsong · l’admin

éditer · administrateurs · 19 captures

Deux colonnes : à gauche, la personne, « Nouvelle chanson », « Sources & import » et l’arbre des chansons ; à droite, la chanson ouverte : métadonnées, styles en pastilles, liens, leçons, fichiers, et le contenu en trois onglets (Éditer, Blocs, Aperçu). Dialogues pour créer, déplacer, supprimer ; bandeau quand la session expire.

songbook

le recueil · public en lecture · 33 captures

Une barre du haut (Songs, Artists, Sign In, recherche, thème), une liste de chansons, et la page d’une chanson en police à chasse fixe : les accords au-dessus des syllabes, le refrain en retrait. En bas, une barre d’outils : taille du texte, transposition, accords affichés ou non, plein écran. L’administrateur édite dans un éditeur de code (Monaco) avec coloration ChordPro.

À noter : interface en anglais ; l’éditeur sans connexion répond par une page brute « Unauthorized » ; la page d’admin est une liste de boutons.

users

la porte d’entrée · page de connexion publique · 29 captures

La page de connexion est l’entrée de tous les sites protégés ; elle reste un vrai formulaire, que les gestionnaires de mots de passe reconnaissent. Une fois connecté : profil, mot de passe et, pour les administrateurs, gestion des comptes et configuration du serveur, par un menu sous le nom de la personne.

À noter : la page de connexion ne dit pas vers quel site on va ; son titre est le nom du serveur ; le profil est presque vide.

components

la bibliothèque · public · 92 captures

Le site de documentation montre chaque composant en démo avec son API, et un guide de styles en 22 sections : jetons, boutons, formulaires, listes, tableaux, navigation, messages, popovers, dialogues, contrôles de lecteur. Toutes les sections sont dans la galerie, en clair et en sombre.

Le système de design actuel

Les fichiers sources sont dans design-system/ du dossier : variables.css, light.css, dark.css, la feuille complète mesnos.style.css et l’API des composants custom-elements.json.

Typographie, espaces, motifs

Typographie

Inter pour le texte, une pile monospace système pour le code et les paroles de songbook. Échelle de 10 à 30 px sur une base de 16 px ; graisses 400 à 700.

Espaces et tailles

Base 4 px (4 à 48). Cible tactile minimale 44 px ; boutons de 24 à 48 px ; rayons 4 / 8 / 12 / 16 px ; conteneurs de 320 à 1280 px.

Motifs CSS, sans JavaScript

.topnav, .item-list, .btn-group, formulaires (.form-stack, .form-grid, .field-row), .table-wrap, .message-*, .popover-menu, .dialog, impression.

Web components

<audio-loop-player>, <video-loop-player>, <youtube-loop-player>, <chord-grid>, <mesnos-dialog> avec confirmDialog() et alertDialog().

Constats à l’œil

Relevés en faisant les captures et dans les notes du carnet. Ce sont des constats, pas des décisions.

  1. Pas d’identité commune visible. Chaque site a son en-tête (barre complète dans songbook, rien dans learnsong, nom du serveur et menu dans users) et sa couleur de favicon (orange pour songbook, slate blue pour learnsong, olive pour son admin).
  2. La couleur d’action change : slate blue pour le bouton principal en clair, bleu vif en sombre, olive pour l’admin learnsong, les lecteurs et la barre de songbook.
  3. Deux langues d’interface : learnsong (« Songs », « Local Practice Files », lecteurs) et songbook en anglais ; l’admin learnsong et users en français.
  4. Aucune navigation entre les sites : on passe de learnsong à son admin par un ⚙️, et rien ne mène de learnsong à songbook ni au profil.
  5. L’état de connexion n’est visible nulle part hors de users.
  6. Les lecteurs sont denses : une dizaine de petits contrôles sur une ligne, que la page d’une chanson empile.
  7. Les états vides et les erreurs sont peu travaillés : accueil de learnsong en liste à puces, « Unauthorized » brut dans songbook, profil presque vide dans users.
  8. Le sombre est quasi noir (#0f0f0f), les titres orange et olive y sont conservés.

Les contraintes à respecter

  • Clair et sombre pour chaque écran ; par défaut, le choix du système.
  • Mobile : chaque écran doit marcher à 375 px de large.
  • Accessibilité : contraste AA (déjà testé sur les boutons), cibles tactiles de 44 px, clavier partout ; les lecteurs ont des raccourcis clavier.
  • Pas de framework lourd ni d’étape de build : une proposition doit pouvoir s’écrire en HTML, avec les classes de mesnos.style.css et quelques web components.
  • Tout passe par la bibliothèque : couleurs, motifs et composants nouveaux vont dans components ; les sites ne gardent que ce qui leur est propre.
  • La page de connexion reste un vrai formulaire HTML, sans ressource chargée d’un autre service.
  • L’impression : songbook a une mise en page d’impression (la chanson seule, sans barres).

Ce qui s’annonce

  • La page d’un atelier (spécifiée en novembre 2026) : ranger les chansons d’un atelier en sections choisies (« répertoire », « envisagées »), avec un ordre et une note, sans perdre la découverte automatique des nouvelles chansons.
  • Partager avec un groupe (idée, novembre 2026) : inviter une personne par un lien personnel, voir ses appareils, la révoquer ; une page « Ton prénom ? » pour demander l’accès.
  • Dans la bibliothèque : champ à pastilles (<mesnos-tag-input>), bascule de thème (<theme-toggle>), bouton de la personne connectée (<mesnos-user-button>), notifications (<mesnos-toast>).
